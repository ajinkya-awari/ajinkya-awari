## About me

I am an **ML Engineer** currently pursuing an **MSc in Artificial Intelligence for Biomedicine and Healthcare at University College London (UCL), UK**.

I build reproducible biomedical machine-learning systems: evaluation harnesses, leakage-safe pipelines, graph models, protein-learning experiments, clinical retrieval contracts, privacy boundaries, and MLOps tooling. My work emphasizes measurable evidence, provenance, safety checks, and honest limitations.

This portfolio contains **20 public repositories out of 21 numbered projects**. Each project is labelled according to what is genuinely verified: public release, benchmark evidence, synthetic-only validation, partial execution, or an external approval gate. I do not present planning work or synthetic contracts as clinical validation.

## Important limitations

The limitations are part of the results, not hidden details:

- Several projects are synthetic or contract-level releases because restricted datasets, clinical approvals, provider credentials, or model access were not available.
- Project 08 requires MIMIC-III/DUA approval before real-data work.
- Project 14 remains planning-only and has no public repository.
- Project 17 has no released measured epsilon or real-data utility result; the public scope is the synthetic privacy/federated-learning contract layer.
- Project 20 uses a fixed synthetic benchmark. The primary Qwen arm is valid on 86/200 records covering 10/20 tasks; the constrained arm is post-hoc, secondary, and exploratory, so the two arms are not directly comparable.
- Project 07 is a pilot-scale pathology benchmark and is not clinical validation.
- Public repositories do not imply regulatory approval, clinical deployment, or production readiness.

## How I work

- **Contracts before code:** define acceptance criteria and failure states first.
- **Synthetic before restricted:** validate pipeline behavior before requesting sensitive data or external services.
- **Evidence before claims:** preserve test counts, seeds, hashes, provenance, and limitations.
- **Explicit gates:** data, model, provider, GPU, privacy, and publication gates are recorded rather than bypassed.
- **No hidden attribution:** public repositories contain no AI co-author trailers or session transcripts; commit authorship is verified from repository history.
